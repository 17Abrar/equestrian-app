# Cavaliq Code Review: Verification and Action Plan

## 1. Bottom line

Of the 25 external-review claims, 9 are confirmed, 7 are partly true, and 9 are refuted (outdated or factually wrong). The single most important real risk is the absence of any database-level tenant isolation backstop (claim 1): cross-tenant safety rests entirely on application-layer `clubId` scoping, so one future query that forgets its `clubId` predicate can leak across tenants with nothing to catch it. The reviewer was right about that and about the manual-by-email GDPR deletion path (claim 8), but was wrong on most of the "missing infrastructure" claims: CI/CD, tests, branch protection, rate limiting, CSP, backups, and dependency pinning all demonstrably exist.

## 3. What is actually wrong and worth doing (confirmed + partial only)

### Tenant safety

- **(1, Medium, L) No DB-level isolation backstop.** RLS was deliberately removed (`migrations/0011_drop_rls.sql`) because the Neon HTTP driver cannot set `current_setting('app.current_club_id')` and the WS-transaction path cost ~150ms/request. App-layer scoping is thorough and audited (`AUDIT_TENANT_SCOPING.md`, 0 HIGH/MEDIUM across 91 routes), but a single forgotten `eq(table.clubId, X)` leaks cross-tenant. Fix: add defense-in-depth without per-request WS cost. Either (a) force RLS only on the WebSocket `writeTransaction` path where a tx already exists so `SET LOCAL app.current_club_id` is cheap, and/or (b) add a CI ESLint guard (repo already uses `no-restricted-syntax`) that fails any Drizzle query against a tenant table lacking a `clubId` predicate. Keep composite-FK and helper-arg discipline as the primary control.

### Payments / encryption

- **(3, Medium, M) Encryption key rotation runbook is missing and `ENV.md:277` points to a section that does not exist.** Field-level AES-256-GCM encryption itself exists and is documented (`packages/db/src/crypto.ts`), and protects PHI + per-club payment credentials. The gap is master-key rotation / key-loss / re-encryption. Fix: write the promised `INCIDENT_RUNBOOK.md` section covering dual-key decrypt-old/write-new rollover, a re-encryption migration script (none exists today, only one-time plaintext backfills), and the key-loss blast radius (encrypted PHI + payment creds become unrecoverable; clubs must re-paste webhook secrets). Repair the dead `ENV.md` pointer.

### Data / GDPR

- **(8, Medium, L) Account deletion and DSAR are manual-by-email, not programmatic.** `account/delete/route.ts` does no DB writes: it validates, rate-limits, and emails `info@cavaliq.com` with "Action required" steps, returning `{requested:true}`. `privacy/request/route.ts` is the same shape and does not even auto-acknowledge the requester. This is a deliberate, defensible design given cascading equestrian dependencies, but it is correctly described as manual. Fix (if automated erasure is a compliance goal): add a soft-delete + scheduled hard-delete job scoped by Clerk userId across `club_members`, bookings, rider profiles, retaining payment records per tax-retention law. Otherwise: document the 30-day manual SLA and ensure the ops process is actually tracked.

### Mobile

- **(18, Low, M) Cloudflare worker frames are not source-mapped in Sentry.** App/Next build maps are configured and the CI token is wired (`deploy.yml:111`), but the OpenNext worker bundle has no map upload (`wrangler.jsonc` lacks `upload_source_maps`, deploy step does no `sentry-cli sourcemaps upload`). Fix: set `upload_source_maps: true` and add a Sentry map upload for the `.open-next` worker bundle using the same token. Also reconcile the project slug mismatch (`next.config.ts` uses `javascript-nextjs` vs `DEPLOY.md` says `cavaliq-web`), which can split releases and defeat symbolication.
- **(14, Low, M) Push-notification tap-routing spec does not exist.** `apps/mobile` has no `expo-notifications` and no notification-response handler; the feature is gated off (`packages/db/src/queries/notifications.ts:18-19`). A high-level FCM/APNs plan exists in `product-plan.md:1367-1382` but no type-to-screen map. Fix when notifications ship: add `expo-notifications`, register push tokens, implement `addNotificationResponseReceivedListener` reading `notifications.data` JSONB, and document a type-to-route table. Planning gap, not a live bug.
- **(9, Low, M) Booking/payment E2E are `fixme` stubs; no horse E2E.** All three booking/payment scenarios in `e2e/booking-flow.spec.ts` are `test.fixme` scaffolds blocked on seed infra (`docs/e2e-setup.md`); `health.smoke.spec.ts` has 3 runnable nightly smoke tests. Fix: stand up the test club + Clerk/Stripe test creds, remove the `fixme`, and add a horse-flow smoke test.

### Docs / legal

- **(11, Low, S) ARCHITECTURE.md contradicts itself on hosting.** `ARCHITECTURE.md:902-904` says Vercel; README/DEPLOY say Cloudflare Workers via OpenNext, and `:925` even says "All behind Cloudflare." Stale pre-migration spec. Fix: edit those lines to Cloudflare. Docs-only.
- **(16, Low, M) No API lifecycle/sunset policy.** A `v1` URL prefix exists but there is no deprecation window, Deprecation/Sunset headers, or v2 plan. Fix when a v2 becomes likely: add a short API lifecycle policy (RFC 8594 headers, deprecation window, changelog). Not blocking while only first-party v1 exists.
- **(25, Low, S) License is contradictory.** No `LICENSE` file; root and app manifests are `private:true` with no license field, yet 7 sub-packages declare `"MIT"`. Fix: decide intent. If proprietary, set sub-packages to `"UNLICENSED"` or drop the field. If open-sourcing, add a real root LICENSE and matching field. Reconcile the mismatch either way.
- **(20, Low, S) No tags, no CHANGELOG.** Both true (0 tags, no CHANGELOG); the reviewer's commit count of 213 is wrong (actual 217). Fix: optionally adopt SemVer tags or a CHANGELOG; audit-numbered PR commit messages already give a de-facto trail.
- **(21, Low, S) No PR template or contributing guide.** True; `.github/` has only dependabot + workflows. Low impact for a solo/handoff repo (norms live in AGENTS.md/CLAUDE.md). Add a short PR template only if onboarding external contributors.
- **(23, Low, M) No Turborepo remote cache.** True; builds are local-cache only. Optional CI-velocity improvement: set `TURBO_TOKEN`/`TURBO_TEAM` and enable signature verification. Not a correctness or security issue.
- **(24, None, S) No CODEOWNERS.** True but low impact for a single-owner repo; only matters with multiple maintainers and code-owner review enforcement.

## 4. Claims that are outdated or incorrect (push back on these)

- **(2) "No CI/CD pipeline."** Wrong. 4 committed workflows; `ci.yml` gates PRs with secret-scan, dep-audit, typecheck, lint, test, OpenNext build, plus a real-Postgres Neon smoke job; `deploy.yml` auto-deploys to Cloudflare on CI success.
- **(4) "No visible test coverage."** Wrong. 31 test files, ~417 `test`/`it` calls, heavily weighted to tenant isolation, payments, and webhooks.
- **(5) "Rate limiting not implemented; public endpoints unprotected."** Wrong. `@upstash/ratelimit` sliding-window over shared Redis, wired with `failClosed` on discover, public profile, join, support, webhooks, and more.
- **(6) "Realtime channels not checked for tenant leakage."** Moot. There is no realtime layer at all; `ws` is the Neon driver polyfill and Ably appears only in forward-looking legal copy. Community is an explicit pre-launch waitlist.
- **(7) "Most deps pinned to latest."** Wrong. Zero `"latest"`, zero `"*"`; 85 caret, 13 tilde, 21 exact pins, with documented security overrides.
- **(10) "No branch protection."** Wrong. `main` has required status checks, 1 required review, admin enforcement, and force-push/deletion blocked.
- **(12) "Stripe preview/beta API version."** Wrong. `2026-04-22.dahlia` is a dated GA release; `.dahlia` is a normal Stripe codename, not a `.preview` tag.
- **(13) "No backup/recovery procedure documented."** Wrong. `DEPLOY.md:410-489` is a full Neon PITR runbook with runnable `neonctl` commands, a `restore-drill.mjs` script, and a dated drill log.
- **(15) "No CSP headers."** Wrong. `middleware.ts` builds a full per-request nonce-based CSP and attaches it, plus static security headers in `next.config.ts`.
- **(17) "Download links expire after 1hr, no mobile refresh."** Wrong. The only presigned URL is a 5-minute UPLOAD URL; downloads use stable, non-expiring public R2 URLs, so no refresh is needed.
- **(19) "Coupon TOCTOU race."** Wrong. Redemption uses a `FOR UPDATE` row lock plus same-transaction increment, with concurrency tests proving exactly 2 of 5 concurrent redemptions succeed on a `maxUses=2` coupon.
- **(22) "No security disclosure policy."** Essentially false. A complete RFC 9116 `security.txt` exists and is git-tracked and publicly served (the only nuance: no top-level `SECURITY.md` for the GitHub Security tab).
